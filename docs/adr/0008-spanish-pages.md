# 0008. Spanish pages live in es/ and are built from the same layout

Status: Accepted (2026-10-16). The pages are a draft until a fluent speaker reviews them.

## Context
Many families who use the guide speak Spanish at home. Issue #8 asks for Spanish versions of the Playbook and Rules pages, and the quality bar in `docs/ROADMAP.md` asks for Home too, reviewed by a fluent speaker. `languages.html` already links official agency pages in Spanish, but none of our own pages were in Spanish. The site is plain HTML stamped from `src/` by `tools/build.py` (ADR 0003), and every byte on a phone is budgeted (ADR 0007).

## Decision
- **One folder per language.** `src/es/<name>.html` is built to `es/<name>.html` (live: `/internships/es/rules.html`). The English page keeps its address. A Spanish page exists only next to an English page of the same name; the build stops if `src/<name>.html` is missing.
- **One layout.** The Spanish pages use `src/_layout.html`. `src/es/_layout.json` lists each English string in the layout and the Spanish words that replace it, so the head, CSP and footer can never drift apart. The build stops if an English string in that file is no longer in the layout. `tests/es-pages.test.mjs` checks the other way: no text in the built Spanish header and footer is still the English text.
- **Links.** On a page in `es/`, the build adds `../` to every relative link and asset unless the target has a Spanish twin. A link to an English page also gets `hreflang="en"`, and the page text says "(en inglés)" next to it. Official links stay the English page unless the same agency publishes the same document in Spanish and we read it; then the Spanish one is linked. `src/es/_links.json` lists each pair with the date it was read, and lists the English pages that have no Spanish version.
- **Both ways.** A page with a twin carries `<link rel="alternate" hreflang>` for `en`, `es` and `x-default` (English), and a language link at the end of the nav: "Español" with `lang="es"` on the English page, "English" with `lang="en"` on the Spanish page. On a phone it sits inside Menu. The Spanish draft note at the top of each page also links the English page. Pages with no twin are byte for byte unchanged.
- **Scripts.** Home and Rules load only `common.js` and `assets/js/es.js` (`lib: none`). `es.js` puts Spanish on the few words `common.js` writes (Menu, Copied). English pages never load it, so no English page grew in code bytes and no shared ceiling was raised. The age picker and closing-soon list on Home stay English for now; the Spanish page explains this in a block marked `data-es-only` and links the English tool.
- **The Playbook tools in Spanish (2026-10-17).** `es/playbook.html` runs the same `playbook.js` as the English page, with the same markup and ids. Before it, the page loads `assets/js/es-playbook.js`, which sets `TIG.es`: a table of Spanish words keyed by the English text, the status names, the how-chips, the asks, a Spanish date, grade phrase, `Asunto:` split, and the message itself. `playbook.js` passes every English string through `t()`, which is plain `String` when `TIG.es` is missing, so an English page shows exactly what it showed before. Only `es/playbook.html` loads `es-playbook.js`. `lib.js` did not change: the Spanish date, grade and subject helpers live in `es-playbook.js`, because English `playbook.html` had 30 bytes of first-load headroom and every English page that loads `lib.js` would pay for them. `playbook.js` grew 26 bytes, paid for by small cleanups in the same file. `tests/es-playbook.test.mjs` checks that every `t("...")` in `playbook.js` has a Spanish row and every row is used, so an English edit to the tools fails until the Spanish row is updated.
- **Draft until reviewed.** Each `src/es` page header says `review: pending`. While it does, the page shows a draft note at the top, carries `noindex`, and is left out of `sitemap.xml`. When a fluent speaker has reviewed a page, set `review: <name or handle> <YYYY-MM-DD>` and remove the draft note; the build then drops `noindex` and adds the page to the sitemap. The test requires the note while the header says pending.
- **Drift tests.** `tests/es-pages.test.mjs` compares each Spanish page with its English twin inside `main`: the same section ids in the same order, the same number of headings in each section, the same set of numbers, and the same links (an official Spanish twin from `src/es/_links.json` counts as its English page). Blocks only one side has are named on purpose: `data-es-only` on the Spanish side, and a short list of English tool ids in the test, each with a reason. An English edit that changes a number, link or section therefore fails until the Spanish page is updated.
- **Wording.** Plain, warm Spanish for a 12 to 17 year old and their parents, the way a California school writes: tú for the teen, usted inside the sample messages to adults, ustedes for parents and leaders as a group. Numbers, prices and times keep US style (`$16.90`, `8 a. m.`), as California agencies write them in Spanish. No em or en dashes, the same as English.

## Consequences
- Adding a language later is a new folder and a new `_layout.json`; the build loop and tests would need the language code added.
- Every English edit to Home, Playbook or Rules must be carried to the Spanish page in the same pull request, or CI fails on the drift test.
- Spanish pages are not in the root page sweeps (those read the repo root only). The Spanish test runs the checks that matter for them: axe, CSP hashes, byte ceilings, dashes and the draft note.
- The Spanish Playbook loads about 9 KB more first-load code than its English twin (`es-playbook.js`, which carries both the English keys and the Spanish words). The `es/playbook.html` code ceiling in `tests/es-pages.test.mjs` is waiting for a person's approval.
- Not done yet: the Home age picker and closing-soon list in Spanish, Spanish program cards, and the fluent speaker review itself.
