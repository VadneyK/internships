# How to contribute

Thank you for helping. This guide is for students, parents, teachers and developers. You do not need to know how to code to help.
**You must be 13 or older to have a GitHub account. If you are under 18, ask a parent or guardian first.**

Everything happens in public (issues and pull requests), so adults you trust can see it. Please read the
[Code of Conduct](CODE_OF_CONDUCT.md) first. It is short.

## Pick a path

| Path | Time | Coding? | What you do |
|---|---|---|---|
| 1. Report a fix | 5 min | No | Use the [report form](https://github.com/VadneyK/internships/issues/new?template=update-program.yml) when a date, age rule or link is wrong |
| 2. Suggest a program | 15 min | No | Use the [add form](https://github.com/VadneyK/internships/issues/new?template=add-program.yml) |
| 3. Add a program file yourself | 30 min | Barely | Create one small JSON file in the GitHub web editor (steps below) |
| 4. Adopt a region | 1 hour per quarter | No | Re-read the official pages for a region and fix what changed. See [`docs/MAINTAINING.md`](docs/MAINTAINING.md) and [`docs/ADDING_A_REGION.md`](docs/ADDING_A_REGION.md) |
| 5. Improve the site | varies | Yes | Filters, accessibility, translations, a map. Pick an issue labeled `good first issue` |

## Path 3: add a program file in your browser

1. Read the program's **official page**. Check the age rule, pay, dates and how to apply. Our rule: no official page, no card.
2. Open [`docs/program-template.json`](docs/program-template.json) and copy its text.
3. Go to the [`data/programs`](data/programs) folder. Click **Add file, then Create new file**.
4. Name it `<id>.json`, where `<id>` is lowercase words joined by hyphens (example: `oakland-zoo-teen-volunteers.json`).
5. Paste the template and replace every value. Notes on the fields are in [`data/schema/program.schema.json`](data/schema/program.schema.json).
   - `what_you_do`: plain words, about 8th grade reading level, under 260 characters.
   - `deadline_text`: exact dates with the year. If next year's dates are not posted, give last year's and set `deadline_confidence` to `last-year-pattern`.
   - `sources_fetched`: every page you actually read.
   - `verified`: `fetched` only if you read the official page yourself.
6. Click **Commit changes**, choose **Create a new branch**, then **Propose changes** and **Create pull request**.
7. A robot checks your file within a minute. Click "Details" next to any red X to see what to fix. A maintainer will review and merge.

Never use the long dash characters (em dash or en dash). Use a comma, a colon, or the word "to".

## Path 5: work on the code

You need Python 3.10+ (for the data tools) and Node 20+ (only for the tests). The site itself needs neither.

```bash
git clone https://github.com/VadneyK/internships.git
cd internships
pip install jsonschema

python3 tools/validate.py        # check every program file
python3 tools/build_data.py      # data/programs/*.json  ->  data/entries.json, entries.csv, meta.json
python3 tools/build.py           # src/*.html + layout   ->  the pages in the repo root
python3 -m unittest discover -s tests -v
npm ci            # once, installs the page-test tool (jsdom)
node --test tests/*.test.mjs

python3 -m http.server 8000      # then open http://localhost:8000
```

### How the project is organized

| Folder or file | What it is |
|---|---|
| `data/programs/*.json` | **The source of truth.** One file per program. Edit these, never `data/entries.json`. |
| `data/schema/program.schema.json` | The rules every program file must follow |
| `data/entries.json`, `entries.csv`, `meta.json` | Generated by `tools/build_data.py`. Committed so the site works on GitHub Pages without a build step. |
| `data/entries-detail.json` | Generated by `tools/build_data.py`. The long text (who can apply, how to apply, notes) for each program, with the same ids and order as `entries.json`. Read only when a teen opens a card's details. |
| `data/entries-lite.json` | Generated by `tools/build_data.py`. Same ids and order as `entries.json`, without the long text. Read by the Find and Home pages (`assets/js/find.js`, `home.js`). Never edit. |
| `data/entries-core.json` | Generated by `tools/build_data.py`. Only the keys needed to match by age, status, season and region. Read by the Ages 12 to 14 page (`assets/js/younger.js`). Never edit. |
| `data/entries-card.json` | Generated by `tools/build_data.py`. Only the short fields the Calendar, Numbers and Home pages read (`assets/js/calendar.js`, `insights.js`, `home.js`). Never edit. |
| `data/permits.json` | Hand-edited. Work permit rules by state for the permit finder and the More states page (`assets/js/permit.js`, `states.js`). Also read by `interview.js`. |
| `data/calendar.json` | Hand-edited. The note and dated items for the Calendar page (`assets/js/calendar.js`). |
| `data/interview.json` | Hand-edited. Text for the Apply and interview prep page (`assets/js/interview.js`). |
| `data/languages.json` | Hand-edited. Languages, places and links to official translated pages (`assets/js/languages.js`). |
| `data/money.json` | Hand-edited. Pay rates, tax facts and sources for the First paycheck page (`assets/js/paycheck.js`). |
| `data/parents.json` | Hand-edited. Text for the For parents page (`assets/js/parents.js`). |
| `data/safety.json` | Hand-edited. Points, hotlines and gaps for the Safe at work page (`assets/js/safety.js`). |
| `data/transit.json` | Hand-edited. Ride options by city for the Ready page (`assets/js/ready.js`). |
| `data/younger.json` | Hand-edited. Text for the Ages 12 to 14 page (`assets/js/younger.js`). |
| `data/gaps.json` | Hand-edited. Known gaps by area. The Find page reads it (`assets/js/find.js`), and `tools/build.py` writes it into the Contribute page, so rebuild after a change. |
| `src/*.html` and `src/_layout.html` | Page content and the shared header and footer |
| `*.html` in the repo root | Generated by `tools/build.py`. Commit them. |
| `assets/js/lib.js` | Pure logic (filtering, sorting, "effective status"). No DOM. Fully tested. |
| `assets/js/*.js` | One small script per page |
| `assets/css/style.css` | All styles, built on color and type tokens at the top |
| `assets/qr/*.svg` | QR codes for the share page. Made by `tools/make_qr.py`. Commit them. See the section below. |
| `tools/build.py`, `tools/build_data.py`, `tools/validate.py`, `tools/proglib.py` | Build tools. `build.py` makes the pages from `src/`. `build_data.py` makes the generated data. `validate.py` checks every program file. `proglib.py` holds the helpers they share. |
| `tools/linkcheck.py` | Checks every program link and writes a Markdown report. The links workflow runs it every Monday. |
| `tools/freshness.py` | Lists programs that need a re-read, as a Markdown checklist. The freshness workflow runs it on the first of each month. |
| `tools/make_qr.py` | Makes the QR code files in `assets/qr/`. CI does not run it. |
| `tools/art.py` | Makes the decorative splat and swoosh SVGs in `assets/img/`. The output is the same every run. |
| `tools/hygiene.py` | A read-only checklist of soft data problems. It never fails CI. |
| `tools/bench-matches.mjs` | Speed numbers for search, sort and loading. Run it before and after a change to compare. |
| `tests/` | Python and JavaScript tests. See [docs/TESTING.md](docs/TESTING.md). |
| `.github/workflows/` | CI, weekly link check, monthly refresh list |
| `docs/` | Method, maintenance guide, roadmap, classroom lesson plan |

### Share page and QR codes

`share.html` shows QR codes for the whole guide, for each Ignition location and for some tools. Each code is a static file, `assets/qr/<name>.svg`, made by `tools/make_qr.py`. The script needs the `segno` package. Run this from the repo root:

```bash
python3 -m venv v && v/bin/pip install segno && v/bin/python tools/make_qr.py
```

- The script writes `assets/qr/<name>.svg` for each entry in its `LINKS` list. Commit the SVG files.
- Run it only when a link in `LINKS` changes. The file header says so.
- CI does not run the script and does not install `segno`. The Python tests in `tests/test_docs_sync.py` do check that each SVG exists, that its title is the link, and that `share.html` has a card for it.
- The `v` folder is not in `.gitignore`. Do not commit it.
- To add a QR code, add its name and path to `LINKS` in `tools/make_qr.py` and run the script. Then add a card to `src/share.html` with the same `data-name` and a `data-copy-link` with the same link. Then run `python3 tools/build.py`.

### Code conventions

- **No frameworks and no build step for the browser code.** Plain HTML, CSS and JavaScript so any student can read it.
- **Logic goes in `lib.js` with a test.** Page scripts only talk to the page.
- **Accessibility is not optional.** Real buttons and labels, visible focus, color contrast of 4.5 to 1 for text, works at 400 px wide and at 200% zoom.
- **No third-party requests.** No analytics, no CDNs, no tracking pixels. Fonts and images are served from this repo.
- **Escape everything you put into HTML** with `TIG.esc()`. Program text comes from files that anyone can propose.
- **Plain words.** Write for a 12 year old. Short sentences. No em dashes or en dashes.
- Keep pull requests small. One program or one idea at a time.

## What happens after you open a pull request

1. CI runs these checks, in this order (see `.github/workflows/ci.yml`):
   1. Validate every program file (`python3 tools/validate.py`).
   2. Python tests (`python3 -m unittest discover -s tests -v`).
   3. JavaScript tests (`node --test tests/*.test.mjs`).
   4. Rebuild the data and pages, then fail if a page or a main data file (`entries.json`, `entries.csv`, `meta.json`) is out of date.
   5. Dash scan: fail if an em dash or en dash is in the text.
2. A maintainer reads your change and may leave comments. This is how everyone learns. It is not a grade.
3. When it is merged, GitHub Pages updates the site within a few minutes and your name appears in the history.
